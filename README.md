# Alfa Battle 2.0: Credit Scoring on Card Transactions

## О проекте

Этот проект — полный пайплайн решения задачи кредитного скоринга на основе транзакционных данных. Задача взята из соревнования Alfa Battle 2.0 (2020–2021 гг.). Цель — предсказать вероятность дефолта клиента (бинарная классификация) по истории его карточных операций.

В отличие от готовых решений, здесь пайплайн написан с нуля: от чтения сырых parquet-файлов и генерации признаков до обучения модели и валидации.

**Ключевой результат:** модель на LightGBM достигает **AUC ROC 0.726** на валидационной выборке.

## Данные

- **Объём:** ~6 ГБ, 50 файлов parquet, около 270 млн транзакций.
- **Клиенты:** 963 811 уникальных `app_id`.
- **Дисбаланс классов:** доля дефолтов (target = 1) составляет всего **2.76%**.
- **Признаки транзакций:** сумма (`amnt`), MCC-категория, тип операции, флаг ecommerce, день недели, час, количество дней до выдачи кредита (`days_before`) и др.

## Технические особенности реализации

**1. Обработка больших данных без перегрузки памяти.**  
Файлы читаются по одному, признаки агрегируются и накапливаются. Итоговая таблица собирается через `groupby('app_id').sum()`, что позволяет корректно объединить транзакции клиента, которые могли находиться в разных файлах.

**2. Feature Engineering.**  
В итоговом наборе 23 признака. Основные группы:
- Базовые статистики: средний чек, сумма, максимум, стандартное отклонение.
- Временные окна: суммы и количество транзакций за последние 30 и 90 дней.
- Поведенческие признаки:
  - `unique_days` — число уникальных дней с транзакциями (стабильность активности);
  - `night_share` — доля ночных операций;
  - `ecommerce_share` — доля онлайн-покупок;
  - `mcc_2_count`, `mcc_4_count` — количество операций в конкретных MCC-категориях.

**3. Валидация.**  
Используется хронологическое разделение 80/20 (обучение на прошлом, проверка на будущем). Это имитирует реальную задачу банка и исключает утечку данных.

**4. Модель и защита от переобучения.**  
LightGBM с параметрами:
- `num_leaves=15`, `min_data_in_leaf=200` — ограничение сложности деревьев;
- `learning_rate=0.03` — медленное обучение;
- `scale_pos_weight=30` — компенсация сильного дисбаланса классов;
- `early_stopping=50` — остановка при отсутствии улучшений на валидации.

## Результаты и итерации

| Версия | Признаков | AUC ROC |
|--------|-----------|---------|
| Базовая модель | 13 | 0.694 |
| Корректная агрегация | 9 | 0.691 |
| Расширенные признаки | 16 | 0.704 |
| Поведенческие признаки | 13 | 0.696 |
| **Итоговая модель** | **23** | **0.726** |

Финальный прирост обеспечило объединение всех групп признаков: временных окон, поведенческих долей и MCC-статистик.

Данные необходимо скачать с Kaggle (датасет mrmorj/alfabattle-20) и поместить в папку archive/. Затем запустить ноутбук 01_exploration.ipynb.

## Что можно улучшить
Target Encoding для MCC-категорий (доля дефолтов в каждой категории).

Кросс-валидация по времени (TimeSeriesSplit) вместо одного сплита.

Блендинг с CatBoost или RNN-моделью (в соревновании RNN давала ~0.750).
